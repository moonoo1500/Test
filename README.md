## 🚀 Запуск

Проект не требует `npm install` — достаточно Node.js 20+:

```bash
npm run dev          # → http://localhost:5173
npm test             # 29 юнит-тестов на node:test
npm run build        # статический билд в ./dist
```

Открыть `app/index.html` двойным кликом тоже сработает — приложение полностью статическое.

## ✨ Возможности

| | |
| --- | --- |
| **Живой предпросмотр** | рендер на каждое нажатие клавиши, свой парсер Markdown (~200 строк, без marked/DOMPurify) |
| **Безопасность по умолчанию** | вход экранируется до разметки + фильтр схем ссылок → сырой HTML и `javascript:` не проходят |
| **Несколько заметок** | поиск, создание, удаление, автосортировка по дате изменения |
| **Автосохранение** | `localStorage`, дебаунс 400 мс; заметки не улетают на сервер |
| **Форматирование** | тулбар + горячие клавиши `Ctrl+B` / `Ctrl+I` / `Ctrl+E` / `Ctrl+K` / `Ctrl+S` |
| **Экспорт и импорт** | скачивание `.md`, копирование готового HTML, загрузка файла с диска |
| **Тёмная / светлая тема** | CSS-переменные, `prefers-reduced-motion`, `@media` для узких экранов |
| **Статистика** | слова, знаки, время чтения — отдельным чистым модулем |

## 🧱 Структура

```
.
├── app/
│   ├── index.html          разметка экрана
│   ├── styles.css          дизайн-система на CSS-переменных
│   ├── app.js              контроллер: состояние, события, localStorage
│   └── lib/
│       ├── markdown.js     парсер Markdown → HTML (pure ESM, без DOM)
│       └── stats.js        слова / знаки / время чтения / оглавление / diff
├── scripts/
│   ├── dev-server.mjs      статический сервер на node:http (30 строк)
│   └── build.mjs           копирование app/ → dist/ + inline-сборка
├── tests/                  29 тестов на встроенном node:test
└── .github/workflows/ci.yml
```

Логика вынесена из `app.js` в `app/lib/*` специально: эти модули не трогают DOM, поэтому
тестируются «в лоб» — без jsdom и без headless-браузера.

## 🧪 Тесты и CI

```bash
$ npm test
# tests 29
# pass 29
# fail 0
```

GitHub Actions ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)) гоняет тесты и
`node --check` на Node 20/22 по каждому пушу и PR. Ставить зависимости нечем —
`npm ci` в пайплайне сознательно нет, CI от этого летает.

## 📐 Как работает парсер

```
исходник  →  нормализация переносов  →  построчный разбор блоков
          →  escapeHtml(весь текст)   →  инлайн-разметка  →  HTML
```

Порядок критичен: **экранирование предшествует разметке**, поэтому `<script>` из документа
превращается в безопасный `&lt;script&gt;`. Поддержано: заголовки `h1–h6` с якорями, абзацы,
`**bold**`, `*em*`, `~~del~~`, `` `code` ``, блоки ``` fenced ``` с языком, ссылки и картинки,
цитаты, `ul`/`ol`, task-lists `- [x]`, таблицы с выравниванием `:---:`, разделители `---`.

Не поддержано (осознанно, ради ~200 строк вместо ~2000): вложенные списки, HTML-встраивание,
сноски, сырой HTML. Для заметок этого хватает; для издательского пайплайна берите CommonMark.

## 🔒 Модель угроз

Приложение работает только с твоим собственным текстом, но парсер написан так, чтобы
пережить вставку недоверенного Markdown:

- сырой HTML вырезается экранированием на входе;
- схемы URL ограничены `http/https/mailto/tel` и относительными путями;
- внешние ссылки получают `rel="noopener noreferrer"`;
- dev-сервер не отдаёт файлы за пределы `app/`.
