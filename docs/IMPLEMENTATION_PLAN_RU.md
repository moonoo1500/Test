# План реализации и критерии приемки — «Контур Слома» (Fracture Line)

## 1. Концепция и оригинальность
- **Название:** «Контур Слома» (EN: *Fracture Line*)
- **Package ID:** `com.fractureline.demolition`
- **Жанр:** Мобильная физическая 3D-песочница-головоломка с полностью разрушаемой воксельной средой, подготовкой маршрута, структурными обрушениями и управляемой техникой.
- **Сеттинг:** Спецподразделение инженерного демонтажа на заброшенных и аварийных объектах северного архипелага (промзона у причала, горный карьер, арктическая научная станция).
- **Движок:** **Godot 4.7.2-stable** (Mobile Vulkan renderer с автоматическим OpenGL ES 3 fallback на слабых GPU). Профилирование в CI/бенчмарке; GDExtension/C++ применяется только при подтверждении узких мест замерами.
- **Замечание по ветке:** В рамках текущей сессии разработки вся работа ведется в изолированной ветке `arena/37562270-test` от базового коммита `main` (`6e24c77`), без создания посторонних веток.

## 2. Архитектура воксельного мира и разрушений
1. **Чанки 16×16×16 вокселей** (размер вокселя `0.5 м`, чанк `8×8×8 м`).
   - Мир хранится разреженным словарем `Vector3i -> VoxelChunk`.
   - Пустые чанки не выделяют `PackedByteArray`, меш и коллизию (0 байт данных).
2. **Генерация мешей:**
   - Удаление внутренних/смежных граней с проверкой соседних чанков.
   - Greedy meshing по 6 направлениям для одинакового `(material_id, ao_signature)` — многократное сокращение числа треугольников.
   - Запекание 4-углового Vertex AO (ambient occlusion) и мирового процедурного шейдера материалов (1 draw call на чанк).
   - Асинхронная подготовка буферов в `WorkerThreadPool` на основе неизменяемого `ChunkSnapshot`, а коммит меша и коллизии в дерево сцены — с покадровым бюджетом (до `3–6` чанков за кадр в зависимости от профиля).
3. **Агрегированная физика и коллизии:**
   - 3D greedy box decomposition по чанку: вместо 1 коллайдера на воксель создается минимальный набор `BoxShape3D` (единицы-десятки коробок на чанк).
4. **Инкрементальная структурная устойчивость:**
   - После разрушений собирается пограничный фронт уцелевших вокселей.
   - Ограниченный локальный BFS от фронта до опорного слоя (`BEDROCK` / `y <= 1`) с мгновенным ранним выходом.
   - Оторвавшиеся фрагменты извлекаются из статики и превращаются в пулированные `RigidBody3D` (с ограничением бюджета активных тел, напр. `12 / 24 / 36` по профилю) либо рассыпаются на пулированные микро-обломки.
5. **Огонь, дым и взрывы:**
   - Разреженная карта горящих ячеек с профильным лимитом (`24 / 48 / 96` очагов), пошаговым распространением по горючим материалам (`WOOD`, `FUEL`), вторичной детонацией топлива и тушением криопеной.
6. **Формат сохранений (`FLSV` v1):**
   - Компактная RLE-дельта относительно детерминированного генератора уровня + ZSTD-сжатие + сохранение прогресса миссий, таймера тревоги, целей и позиции игрока/техники.

## 3. Игровой объем (MVP → Релиз)
- **Режимы:** Интерактивное обучение (`Тренировочный полигон`, 8 шагов), Свободная песочница (выбор любой из 4 локаций без таймера), Кампания из 4 миссий на 3 оригинальных локациях:
  1. *Ржавый грузовой порт* (`dock`) — Миссия 1 «Причал №7» и Миссия 2 «Швартовый сектор Б».
  2. *Базальтовый карьер* (`quarry`) — Миссия 3 «Базальтовый разрез».
  3. *Крио-терминал «Север»* (`cryo`) — Миссия 4 «Крио-терминал Север».
- **6 оригинальных инструментов/действий:**
  1. Дробильный молот (локальное дробление кирпича/дерева/стекла/бетона)
  2. Термокопьё (точная резка стали и поджиг горючих материалов)
  3. Сейсмический заряд (метаемый липкий заряд с дистанционным подрывом и взрывной волной)
  4. Крио-пена (тушение пожаров и охлаждение)
  5. Укладчик мостов (построение временных воксельных переправ и пандусов)
  6. Захват грузов (перенос и бросок физических объектов и оторванных обломков)
- **2 управляемых транспортных средства:**
  1. Портовый погрузчик (манёвренная машина для расчистки деревянных и кирпичных заграждений)
  2. Карьерный тягач (тяжёлая бронированная машина, пробивающая бетонные стены)

## 4. Измеримые критерии качества (KPI)
1. **Чанковая и коллизионная оптимизация:** greedy meshing снижает число граней на типовом строительном чанке >= 60% относительно наивного повоксельного меша; сплошной чанк 16³ дает ровно 1 `BoxShape3D`.
2. **Производительность (ориентир Snapdragon 778G / 6 ГБ RAM, профиль Medium):**
   - Обычная сцена: <= 16–33 мс/кадр (30–60 FPS), без блокировки UI при взрывах (бюджетирование пересборки чанков).
   - Память процесса в CI-бенчмарке: << 512 МБ (целевой потолок на телефоне <= 1.5 ГБ).
   - Размер `arm64-v8a` APK: <= 100 МБ (лимит 500 МБ).
3. **Локализация:** 100% ключей синхронизированы между `ru` и `en`, 0 зашитых пользовательских строк, 0 пропущенных глифов кириллицы в шрифте.
4. **CI и тесты:** 100% прохождение `gdlint`, unit/integration-тестов в `godot --headless`, прохождение бенчмарк-сценария, успешный экспорт и криптографическая проверка подписи APK (`apksigner verify`), публикация в GitHub Release.
